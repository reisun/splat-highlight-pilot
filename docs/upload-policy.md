# 動画アップロードの制限

1ファイル15GB（15,000,000,000バイト）、1メッセージ1MiB。ブラウザの申告だけでなく実受信量を検証し、申告との不一致・上限超過では中断する。Uvicornもメッセージ1MiB・受信キュー2件で制限する。

開始メッセージは接続から10秒以内、動画受信の無通信は60秒、アップロード全体は最大3600秒。経過時間はmonotonic時計で測定する。開始から120秒は速度判定を猶予し、その後、実測平均速度からの全体所要時間（申告サイズ × 経過秒 / 受信バイト）が3600秒を超える状態が60秒続けば中断する。速度が回復すれば低速継続時間をリセットする。容量の小さい動画は低速でも1時間以内の見込みなら受け付ける。

15GBを3600秒で送るには平均4.17MB/秒、約33.3Mbpsが必要。判定は回線契約速度ではなく、サーバーの実受信量による。切断・制限違反では途中ファイルを削除して受付を解放する。

アップロードからスキャン・解析・変換・結果保存・後片付けまで全体を排他とする。処理中のリクエストは動画受信・ジョブ作成前に拒否し、待機チケットを発行しない。ブラウザはreadyを待ち、1MiB送信ごとに進捗応答を待つため、大容量ファイル全体を送信バッファへ積まない。

処理記録は永続保存する。受付が再起動した場合、中断した処理を自動再開せず、analyzerと変換の停止確認後に失敗扱いで後片付けし、新規受付を再開する。解析状態が不明なら受付を閉じたままにする。FFmpegはロックFDを継承し、実行が残る間は再受付できない。PID照合ではLinuxの起動時刻も比較し、PID再利用を区別する。

`GET /processing` は受付記録・解析実状態・FFmpeg実状態の比較用。推定終了時刻は現在不明としてnullを返す。受付可否を推定時刻や記録の経過時間だけで変更しない。

結果画面のダウンロードボタンには「約12時間有効」と表示する。現在の運用では結果ファイルの更新から12時間後に自動削除対象となる。削除は1時間ごとに確認し、処理中は休止するため、表示は有効期間の目安とする。

単一Linuxホスト、pilotとanalyzerは各1workerで運用する。analyzerの `/processing` 対応版を先に反映し、pilot APIとWebUIを同時に更新する。旧WebUIを開いたままの場合は再読込する。巻き戻す場合もAPIとWebUIを揃える。共有volume内の `.state` は保持し、ロックファイルを削除して復旧しない。
